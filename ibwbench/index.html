ibwbench

A held-out benchmark measuring whether a language model can reason about in-building wireless and distributed antenna systems — the domain the general telecom LLM suites leave uncovered.

Why it exists

GSMA's Open-Telco LLM Benchmarks — the reference telecom suite — contain no items for indoor, in-building, DAS, distributed antenna, PIM, intermod, or EIRP (checked against GSMA/leaderboard, Aug 2026). General telecom-math sets cover link-budget arithmetic but not the in-building core: public-safety DAS code compliance, passive intermodulation product math, distributed-antenna topology and link design, and installation closeout QA. ibwbench fills that gap.

It discriminates. Three distinct, well-separated scores. And note the ordering: the 4B model beats the older 70B. The empty-response guard

This benchmark could have silently produced fiction. With a stop sequence like ['\n\n'], some small models returned empty strings — which a naive harness scores as a clean exact_match = 0 and prints in a tidy results table. A broken or unreachable model then reads as merely bad, and the table looks trustworthy. So the runner refuses to score a run where more than 5% of responses are empty:

frac = empty / total
if frac > 0.05:
    raise SystemExit(
        f"ABORT: {frac:.0%} empty responses — this is a broken/"
        f"unreachable model, NOT a score of 0.")

The stop sequence is removed entirely (until: []), and scoring parses the final number and compares as a float, so 33 and 33.0 are not a false miss. Every gold answer was verified by independent recomputation before any model ran.

Controls

Stated-fact control. An invented constant given in the prompt. A model that misses it is broken. Passed on all three models — the harness scores a gettable item.
Contamination canary. An invented constant defined only inside ibwbench and never shown in the prompt. An honest model must miss it; a correct answer would mean the benchmark leaked into training data. Failed on all three models — no leak.

Protocol & reproducibility

  • Format: generate_until, numeric exact-match. Multiple-choice / loglikelihood scoring is unsupported against a local OpenAI-compatible endpoint, so every item is free-generation with one unambiguous numeric answer.
  • Content: invented site geometry over public engineering standards. No real project files; questions concern code requirements (facts), and copyrighted standard text is not reproduced.
  • Runs anywhere with an OpenAI-compatible chat endpoint via lm-eval and the shipped task file + runner.
python3 run_ibwbench.py --model <name> --base <endpoint> --concurrent 8

The full item set, task config, runner, dataset card, and per-model logs are released as the ibwbench dataset.
